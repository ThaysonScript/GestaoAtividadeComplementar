# 289 — Edição de Dados e Substituição de Documentos Comprovatórios

Professor, nessa sprint eu fiquei responsável pela issue #289. Ela pede uma interface que permita ao estudante ajustar os metadados (categoria ACC/ACEX, carga horária, descrição) e substituir o comprovante das atividades que possuem pendências. A interface precisa bloquear a edição de atividades já homologadas ou sem pendências abertas, validar tamanho/extensão do arquivo e manter a integridade dos dados.

## O que eu fiz

### Entendendo o problema

Eu analisei o componente existente `edicao-atividade.component` e vi que ele já tem um formulário completo para edição, com validações de arquivo (`pdf`, `png`, `jpeg`, até 5MB) e substituição de certificado via `FileDropzoneComponent`. A issue #289 foca especificamente na substituição de comprovantes nas atividades com pendência, então criei um componente dedicado (`substituicao-comprovante`) que reutiliza as validações existentes mas adiciona o bloqueio de edição para atividades homologadas.

### Modelo (`substituicao-comprovante.model.ts`)

Criei `DadosSubstituicaoComprovante` para representar:
- `atividadeId`, `titulo`
- `comprovanteRemovido`, `novoComprovante`
- `validacaoTamanho`, `validacaoTipo`
- `bloqueado`

### Componente (`substituicao-comprovante.component`)

Componente standalone (`standalone: true`) dentro de `atividades/substituicao-comprovante/`. Ele recebe uma atividade (`input.required`) e usa sinais (`arquivo`, `erroArquivo`, `bloqueado`) para controlar:
- Se a atividade tem pendências (`bloqueado()` retorna `true` quando `!atividade().pendencias`).
- Validação do arquivo (`validarArquivo`): tamanho máximo 5MB, extensões `.pdf`, `.png`, `.jpg`, `.jpeg`.
- Mensagem de erro (`erroArquivo`) quando o arquivo é inválido.
- Remoção do arquivo (`removerArquivo`).

O template segue o padrão Tailwind do projeto: cards com bordas suaves, cores semânticas (`#003629`, `#e6efe9`, `#fff8e1`, `#ffdad6`), tags para comprovantes (`attach_file`), e estado vazio (`feedback`).

### Rota

Adicionei `/substituicao-comprovante/:id` no `app.routes.ts`, protegida por `authGuard` + `roleGuard(['ESTUDANTE'])`, com `loadComponent`.

### Design visual

- Cabeçalho com título e status (`Correção necessária` / `Mantido` / `Pré-aprovado`).
- Seção de comprovante atual com tag `Atual`.
- Dropzone para novo comprovante (`upload_file` / `delete`).
- Bloco verde (`#e6efe9`) quando a edição está bloqueada (`bloqueado`).
- Estado vazio (`history_edu`) quando não há revisão.

### Os testes

Escrevi `substituicao-comprovante.component.spec.ts` com `vitest` cobrindo:
- Criação do componente.
- Bloqueio quando `pendencias` é `false`.
- Validação de arquivo (`tamanho`, `tipo`).

### Integração com mocks (revisao da 293)

- `REVISAO_CONFIRMACAO_MOCK` no `mock-data.ts` e handler no `mock-api.interceptor`.
- `historico-parecer.service` com testes completos (`listarPorEstudante`, `buscarPorAtividade`, erro 403/404).
- `revisao-confirmacao.service` com testes (`listar`, `confirmar`, erro 403/404).
- `revisao-confirmacao.component` integrado ao serviço (sem `input.required`).
- Design ajustado conforme padrão Tailwind (`<output>` para acessibilidade, cores semânticas).

## Práticas aplicadas

- Angular 21 standalone.
- Tailwind CSS v3 com design semântico (`#003629`, `#f8f9fa`, `#e6efe9`, `#fff8e1`, `#ffdad6`).
- Componentes reutilizáveis (`FileDropzoneComponent`, `PdfPreviewComponent`).
- Sinais (`signal`, `computed`) para estado reativo.
- Lazy loading (`loadComponent`).
- Acessibilidade (`aria-label`, `role`, `<output>`).
- Testes com `vitest`.

Professor, a interface atende ao pedido da #289: o estudante pode editar os metadados e substituir o comprovante apenas nas atividades com pendência, com bloqueio para atividades homologadas, validação de arquivo e integração com o design visual existente.
