# 288 — Interface de Pendências e Histórico de Pareceres

Professor, nessa sprint eu fiquei responsável pela issue #288. Ela pede uma interface onde o estudante consiga ver as atividades que estão com pendências e consultar o histórico completo dos pareceres que o avaliador fez, com as justificativas, observações e até os artigos do regulamento que foram citados. Além disso, a interface precisa destacar visualmente quando é uma correção, quando o item foi mantido ou quando está pré-aprovado. E ainda tem que preservar a linha do tempo de todas as avaliações, para o estudante poder auditar o que aconteceu com cada atividade.

## O que eu fiz

### Entendendo o problema

No começo, eu li todos os arquivos do frontend para entender como o projeto está organizado. Vi que é um Angular 21 standalone, com Tailwind, usando `signal` e `computed`. O domínio de atividades já tinha um componente de parecer automatizado (`parecer-card`), mas ele mostra só a auditoria da IA (deferido, indeferido, ambíguo). A issue #288 fala do **parecer humano** do avaliador, que vem das solicitações de validação (`solicitacao`). Então eu percebi que precisava cruzar os dados das atividades com o histórico das solicitações.

### Criando a estrutura de dados

Eu criei um arquivo novo, `historico-parecer.model.ts`, para representar o que a interface precisa:

- Cada avaliação do avaliador (`ParecerAvaliadorHistorico`) tem: a data, o status da solicitação, o tipo do parecer (`CORRECAO`, `MANTIDO`, `PRE_APROVADO`), a justificativa, as observações, o artigo do regulamento e as horas aproveitáveis.
- A atividade (`AtividadeComHistoricoParecer`) agrupa todos esses pareceres e indica se ainda existe pendência ativa.

### O componente

Eu decidi criar um componente standalone (`pendencias-historico.component`) dentro de uma nova pasta `pendencias/`. Ele usa sinais (`carregando`, `mensagemErro`, `atividades`) para controlar o estado. Quando o componente inicia, ele carrega os dados (por enquanto com um mock interno, mas o serviço já está pronto para conectar ao backend).

No template, eu usei Tailwind para manter a consistência visual do projeto. A página tem:
- Um cabeçalho com título e link de volta para o dashboard.
- Estado de carregamento com o spinner (`material-symbols-outlined animate-spin`).
- Estado de erro com `role="alert"` e botão de tentar novamente.
- Estado vazio com mensagem e ícone (`history_edu`).
- Para cada atividade, um card (`bg-white rounded-xl shadow-[...]`) que muda de cor no cabeçalho dependendo se há pendência ativa (`bg-[#ffdad6]/10`) ou não (`bg-[#e6efe9]/20`).

Dentro do card, eu fiz uma linha do tempo vertical (`ol` com `border-l-2`) para cada parecer. Cada item mostra:
- Um ponto colorido (vermelho para correção, amarelo para mantido, verde para pré-aprovado).
- A tag do tipo de parecer.
- A data formatada (`dataFormatada`).
- A justificativa, se existir.
- Um bloco destacado para as observações do avaliador.
- O artigo do regulamento e a carga horária aproveitável, quando aplicável.

### O destaque visual

A issue pede destaque diferenciado para correção, mantido e pré-aprovado. Eu implementei isso com `ngClass` tanto na tag de status quanto no ponto da timeline. As cores seguem o padrão semântico do projeto (

- `#ba1a1a` / `#ffdad6` para erro/pendência
- `#b78103` / `#fff8e1` para atenção/mantido
- `#003629` / `#e6efe9` para aprovado/pré-aprovado

### A rota

Eu adicionei a rota `/pendencias` no `app.routes.ts`, com `loadComponent` (lazy loading) e protegida por `authGuard` e `roleGuard(['ESTUDANTE'])`, igual às outras rotas do estudante.

### O serviço

Criei `historico-parecer.service.ts` para, quando for integrado, buscar os dados do endpoint `/historico-pareceres`. Ele já trata erros (403, 404, etc.) traduzindo para mensagens de domínio, igual aos outros serviços (`solicitacao.service`, `atividade.service`).

### Os testes

Escrevi `pendencias-historico.component.spec.ts` com `vitest`. Testei:
- Se o componente é criado.
- Se o carregamento começa como `true`.
- Se `semAtividades` funciona quando a lista está vazia.
- Se `temPendencias` detecta corretamente quando há uma atividade com `pendenciasAtivas: true`.
- Se `classeParecer` retorna as classes corretas para cada tipo.
- Se a formatação de data funciona.

## O que ainda pode ser feito

O componente está usando um `setTimeout` com dados simulados (`mock`), porque o backend ainda não tem o endpoint de histórico de pareceres por estudante. O serviço (`historico-parecer.service`) já está pronto. Quando o backend implementar o endpoint, é só trocar o `setTimeout` pela chamada `this.historicoService.listarPorEstudante().subscribe(...)` dentro do componente.

## Práticas que eu usei

- Angular 21 standalone (sem módulos).
- Tailwind CSS v3, com as cores do design system (`#003629`, `#f8f9fa`, etc.).
- Componentes reutilizáveis e sinais (`signal` e `computed`).
- Lazy loading (`loadComponent`).
- Testes com `vitest`.
- Acessibilidade (`role="alert"`, `aria-label`, `time`, `section`).

O componente e o serviço (`historico-parecer.service`) foram integrados ao mock (`REVISAO_CONFIRMACAO_MOCK`) e a interface preserva a linha do tempo das avaliações (`ol` com `time`) conforme o escopo. O componente usa `signal` para carregar os dados via serviço quando integrado ao backend.

Professor, a interface atende ao que a issue #288 pede: o estudante pode ver as pendências, consultar os pareceres detalhados do avaliador com as justificativas e observações, e acompanhar a linha do tempo das avaliações anteriores.
